# Glossary Maintenance

Use the existing `DOMAIN.md` structure when it is clear. Otherwise, use concise records:

```md
### Canonical Term
Definition: What the concept means and how it differs from nearby concepts.
Aliases: Recognized synonyms, if any.
Discouraged terms: Terms that cause ambiguity or drift, if any.
Notes: Scope, lifecycle, or boundary details needed for correct use.
```

Keep unresolved decisions under `Open Questions`. Do not move a proposed term into the approved vocabulary until the user or project authority resolves it. Create a missing glossary only when the user asks to bootstrap or document the language.
